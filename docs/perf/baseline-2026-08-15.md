# Emitter refactor — performance baseline

Captured **2026-08-15**, immediately before the .NET backend refactor began, against the
unmodified `src/ProLang/Compiler/Emitter.cs` (2,115 lines).

Every later phase is measured against these numbers.

```
dotnet run -c Release --project src/ProLang.Benchmarks -- --filter "*" --job short
```

Machine: Windows 11 Pro 22631, .NET SDK 10.0.400. `--job short` — wide error bars, so treat these
as orders of magnitude rather than precise figures. Re-run with the default job before claiming a
specific percentage win.

---

## The headline finding

**Emission accounts for roughly 99% of compile time, and almost none of it is code generation.**

| Workload | Parse | Bind + Lower | Emit | Emit ÷ Parse |
|---|---:|---:|---:|---:|
| Simple (~8 lines) | 5.3 µs | 15.3 µs | **11,069 µs** | 2,097× |
| Structs (~55 lines) | 32.7 µs | 57.0 µs | **13,180 µs** | 410× |
| Strings (~65 lines) | 46.7 µs | 102.5 µs | **10,981 µs** | 235× |
| Expressions (~70 lines) | 61.0 µs | 76.9 µs | **10,135 µs** | 168× |
| Large (~140 lines) | 242.8 µs | 535.4 µs | **16,405 µs** | 68× |

Allocation tells the same story — emission allocates ~7.6 MB regardless of program size, against
9–300 KB for parsing:

| Workload | Parse | Bind + Lower | Emit |
|---|---:|---:|---:|
| Simple | 9.0 KB | 10.3 KB | **7,611 KB** |
| Large | 300.7 KB | 281.2 KB | **7,709 KB** |

## Why: emission cost is fixed, not proportional to the program

From `EmitterBenchmarks`, which scales builtin call sites while holding everything else constant:

| Call sites | Emit (intrinsic-heavy) | Emit (minimal program) | Allocated |
|---:|---:|---:|---:|
| 10 | 8.78 ms | 9.07 ms | 7.45 MB |
| 100 | 9.28 ms | 9.97 ms | 7.54 MB |
| 400 | 11.88 ms | 10.29 ms | 7.84 MB |

A 40× increase in call sites costs about 3 ms and 0.4 MB. The other ~9 ms and ~7.4 MB are paid
before any IL is emitted at all.

That fixed cost is `Emitter.LoadRuntimeAssemblies` (`Emitter.cs:91-215`), which runs from the
`Emitter` **constructor** and calls `AssemblyDefinition.ReadAssembly` over a hardcoded list of
twelve reference assemblies — `System.Private.CoreLib.dll` among them — on **every emit**.
Nothing is cached between `Emitter` instances.

**Implication for the refactor:** the largest available win is not the uncached `ResolveMethod`
(though that is real and sits inside this same area). It is reusing the loaded assembly set across
emits, and/or loading assemblies lazily on first resolution miss rather than eagerly loading all
twelve. This is Phase 3 work, and extracting `ReferenceAssemblyLocator` in Phase 1 is what makes
it a contained change.

For the CLI, which emits once per process, this is a fixed ~10 ms tax on every compile. For the
test suite, the REPL, and any multi-file or watch scenario, it is paid per emit.

## Correcting the previously published numbers

`COMPREHENSIVE_BENCHMARKS.md` documents figures such as "EmitOnly: 24.9 µs (12.00 KB allocated)"
and "Full Pipeline - Simple: 145.9 µs". **Those measurements were not real.**

Two independent defects made the old suite measure nothing:

1. **The workloads never compiled.** Every generated program used `var x = 5`, but ProLang's
   binding keyword is `let`. Binding failed on all five workloads.
2. **`Emitter.Emit` returns early when the program carries diagnostics.** With binding broken, no
   IL was ever generated — the "emission" benchmarks measured a dictionary lookup and a return.

The old suite also had structural problems: `BindOnly_*` never bound anything (`GlobalScope` is
lazy and `ProLangCompilation.Create` does not force it); `EmitOnly_*` was byte-for-byte the same
work as `FullCompile_*`; every emit benchmark wrote a real `.dll` inside the measured region; and
`Program.cs` used `BenchmarkRunner` rather than `BenchmarkSwitcher`, so the documented `--filter`
switch was silently ignored.

`src/BenchmarkDotNet.Artifacts/results/` holds results for three benchmark methods that no longer
exist. They predate commit `77ad8fa` and must not be used as a baseline.

### What now prevents a repeat

`BenchmarkPrograms.Bind` throws from `[GlobalSetup]` if a workload fails to parse or bind. A
workload that stops compiling aborts the run instead of reporting an unbeatable score.

## Result after caching the reference assemblies

`ReferenceAssemblyLocator.LoadRuntimeAssemblies` now caches its result for the process lifetime,
and `ReferenceResolver.ResolveMethod` caches by member signature. Emitted IL is byte-identical —
all 34 golden snapshots and 20 output assertions still pass unchanged.

| Benchmark | Before | After | Change |
|---|---:|---:|---:|
| Emit, cold start | 9.07 ms | 0.44 ms | **20× faster** |
| Emit, cold start (allocated) | 7.43 MB | 35.8 KB | **213× less** |
| Emit, 400 call sites | 11.88 ms | 0.94 ms | **12.6× faster** |
| Emit, 400 call sites (allocated) | 7.84 MB | 340 KB | **23× less** |
| Full test suite wall clock | 8 s | 4 s | 2× faster |

Emission cost now scales with program size instead of being dominated by a flat startup tax:
fixed overhead holds at ~0.44 ms / 35.8 KB while the measured cost grows with call sites.

### After moving builtins into ProLang.Runtime

Emission then took on one extra reference-assembly read — `ProLang.Runtime.dll` — which shows up
as a small, flat addition to cold start:

| Benchmark | Original | After caching | After runtime library |
|---|---:|---:|---:|
| Emit, cold start | 9.07 ms | 0.44 ms | 0.65 ms |
| Emit, cold start (allocated) | 7.43 MB | 35.8 KB | 45.8 KB |
| Emit, 400 call sites | 11.88 ms | 0.94 ms | 1.33 ms |

Still roughly 14× faster and 160× leaner than where it started, and the shape is the one you
want: cold start is flat while measured cost scales with the size of the program.

Two caveats on reading these numbers:

- They are **amortised**. The first emit in a process still reads the reference assemblies. A
  single CLI invocation that compiles one file therefore sees a smaller improvement than the
  table suggests; the test suite, benchmarks, and multi-file builds see the full one.
- `--job short` again. Re-measure with the default job before quoting a precise multiple.

## Running the suite

```bash
# Everything
dotnet run -c Release --project src/ProLang.Benchmarks -- --filter "*"

# Emitter-specific, which is what the refactor moves
dotnet run -c Release --project src/ProLang.Benchmarks -- --filter "*EmitterBenchmarks*"

# Quick pass while iterating; wide error bars, not for recording a baseline
dotnet run -c Release --project src/ProLang.Benchmarks -- --filter "*" --job short
```

`--filter` works now that the entry point uses `BenchmarkSwitcher`.
