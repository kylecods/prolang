# C# NativeAOT MIPS runtime: cube baseline, 2026-10-19

The [runtime](../../runtime/mips-cs/README.md) loads the normal MSIL build of
`examples/18-psp-cube/psp_cube.prl`, including the UI toolkit, and runs it through an IL
interpreter, baseline MIPS templates, and optimized MIPS templates. The C# host was built
both with CoreCLR and with NativeAOT. These are **desktop headless** work measurements,
not PSP hardware timings or FPS estimates.

Environment: Windows 10.0.26300, x64, .NET 10.0.8, SDK 10.0.300. Native executable:
2,791,936 bytes. Five measured runs per mode after a complete warmup; 60 frames per run;
first frame excluded. Each sample is the median of its remaining frame work times, and
the table is the median across samples. CoreCLR tiered compilation and ReadyToRun were
disabled. Counters were enabled in every mode.

| Host | Execution | Median work ms/frame | Sample range ms | Managed bytes/run |
| --- | --- | ---: | ---: | ---: |
| NativeAOT | IL | 0.7952 | 0.7896–1.2409 | 2,449,368 |
| NativeAOT | MIPS baseline | 1.6041 | 1.5253–2.5313 | 2,449,896 |
| NativeAOT | MIPS optimized | 1.4188 | 1.4014–1.4912 | 2,450,232 |
| CoreCLR | IL | 0.9891 | 0.9036–1.0180 | 2,448,876 |
| CoreCLR | MIPS baseline | 1.5636 | 1.5516–1.5762 | 2,449,200 |
| CoreCLR | MIPS optimized | 1.2961 | 1.1369–1.3844 | 2,449,334 |

Allocations include VM setup; measured runs recorded no gen 0/1/2 collections. Forced
collections between samples, loading, guest compilation, SVG capture and report/disassembly
writing were outside the work timing boundary. The host supplies a deterministic application
clock, headless drawing calls and injected Start input. It does no GPU work or rasterization.
These short measurements show desktop timing variation; instruction counts are deterministic.

## Optimizations and evidence

Both MIPS modes use resolved metadata, checked integer templates and stack verification for
fixed frame offsets. Optimized mode additionally folds 58 static calls to parameterless
constant-returning functions and fuses 219 static constant/arithmetic pairs, preserving every
branch target. The table below averages frames 2..60.

| Metric | Baseline MIPS | Optimized MIPS |
| --- | ---: | ---: |
| Executed MIPS words/frame | 274,186 | 229,364 |
| Checked service bridges/frame | 11,911 | 10,039 |
| Emitted code bytes | 87,316 | 79,252 |

Across the complete run, executed MIPS instructions fell **16.36%**. NativeAOT's measured
baseline/optimized work ratio was **1.131×**; CoreCLR's was **1.206×**. The direct IL engine
was faster than emulated MIPS on this host. The MIPS engine decodes actual machine words,
executes branch delay slots, and uses counted services for complex operations; it does not
execute a predecoded substitute for the words.

The hottest optimized method by operation count was `Ui__get`: 824,040 dispatched IL groups
and 39,240 calls across 60 frames, followed by `Ui__node` with 620,820 groups. These are
instrumented counts, not sampled CPU time.

## Correctness

All three engines produced 60 matching cube frames, with exactly 12 edges per frame and
changing geometry. Every frame's edge hash and draw counts also matched the existing
V/PPSSPP reference. That historical log was read, not re-executed during this measurement.

- Cube assembly SHA256: `5F26494A149D9BC7AC369BEA2321BD4915039708A95B9B52D374B6E4D051DAE8`
- V reference log SHA256: `235728A48B0AF9502B52629FA35A0EC2F10BFAC275A7AB8661D5CEB252A12F96`
- 54 unit checks cover decoding, stack verification, arithmetic, MIPS encodings, branch
  targets, a non-nop delay slot and error paths.
- All nine V fixtures passed on each of the three engines on both host variants. Four
  console fixtures were compared with real .NET execution; the remaining fixtures exercise
  PSP bridging and explicit failure diagnostics.

The compatibility profile is bounded and experimental. Temporary object handles are retained
until the VM run ends. Guest binaries use a desktop service ABI and cannot be installed as a
PSP executable. See the runtime README for limits and supported operations.

## Reproduce and inspect instructions

```powershell
./runtime/mips-cs/test.ps1
./runtime/mips-cs/profile.ps1 -Samples 5 -Frames 60 -VLog artifacts/psp-tests/cube/runtime.log
./runtime/mips-cs/test.ps1 -SkipBuild -NativeExe "$PWD/artifacts/mips-cs/native/ProLang.Mips.exe"
```

Omit `-VLog` when the historical reference is unavailable; C# differential checks still run.
Each compilation assigns a new module identity, so a fresh cube DLL can have a different
SHA256 while its program and frame hashes remain the same.

The generated `artifacts/mips-cs/aot/report.html` and `jit/report.html` include raw CSVs,
frame previews and inline instruction excerpts. `il.txt` shows guest IL; `host-il.txt` shows
the original C# IL of `MipsCpu.Execute` and `Vm.Step`; `optimized.txt` shows the emitted MIPS
words mapped back to guest IL. `host-jit.txt` shows those host methods' CoreCLR x64
instructions; `host-aot-hot.txt` shows their named NativeAOT x64 instructions. NativeAOT
has no host JIT. Full host AOT disassembly is preserved separately in `host-aot.txt`.
